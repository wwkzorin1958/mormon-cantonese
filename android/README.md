# Android app — 摩爾門經（廣東話）

Companion app to the podcast feed: the same 245 recordings, with one big **繼續聆聽** button
instead of a podcast client.

**Status:** compiles and produces a working debug APK (`BUILD SUCCESSFUL`, 2 min 7 s,
14 MB). Not yet run on a physical device — that is the next step, and the checklist below
says what to look for.

---

## Requirements

- JDK 17
- Android SDK platform 35 + build-tools 35.0.0
- Nothing else: the Gradle wrapper is committed

`local.properties` must point at your SDK (it is machine-specific and not meant to be
committed):

```
sdk.dir=C:/Android/sdk
```

## Build

```bash
cd android
./gradlew assembleDebug          # → app/build/outputs/apk/debug/app-debug.apk
./gradlew assembleRelease        # needs keystore.properties, see below
```

## The manifest is copied in automatically

`build/manifest.json` is generated by `python tools/build_manifest.py` at the repository
root. A Gradle task (`syncContentManifest`) copies it into `app/src/main/assets/` before
every build, so:

- changing the audio and regenerating the manifest is enough — no manual `cp`
- a stale copy cannot be packaged, because the file is overwritten when it differs
- if **both** the generated manifest and the committed asset are missing, the build fails
  with `No manifest found. Run python tools/build_manifest.py`

If `build/manifest.json` is absent but the committed asset exists (a fresh clone), the build
uses the committed copy and logs a warning.

After the Internet Archive upload, run `verify_upload.py --write` — that fills `audioUrl`
for all 245 items — then just rebuild: the new manifest is picked up automatically.

The debug APK installs side by side with the release build (`applicationIdSuffix .debug`),
which is handy for testing without disturbing a copy someone already uses.

## Signing — do this once, then never lose it

```bash
keytool -genkeypair -v -keystore release.jks -alias kcmcelia \
        -keyalg RSA -keysize 4096 -validity 10000
```

Create `android/keystore.properties` (never commit it):

```properties
storeFile=release.jks
storePassword=…
keyAlias=kcmcelia
keyPassword=…
```

Back the `.jks` up on a USB stick **and** on paper. If it is lost, no existing install can
ever be updated again — only replaced by a differently-signed app.

For CI, the same four values live in repository secrets; see
`.github/workflows/android-release.yml`. Encode the keystore with:

```bash
base64 -w0 release.jks        # → KEYSTORE_BASE64
```

## What is implemented

| Area | State |
|---|---|
| Manifest loading from `assets/manifest.json` | done |
| Three screens: Home, Book, Player | done |
| Streaming when online, local playback when downloaded | done |
| `DownloadManager` downloads, Wi-Fi only, all or per book | done |
| Resume position every 5 s, restored on launch | done |
| Autoplay into the next chapter and the next book | done (single queue of 245 items) |
| Lock screen / notification / Bluetooth controls | done via `MediaSessionService` |
| Sleep timer, speed 0.5–2.0, ±30 s | done |
| Battery-optimisation exemption + per-OEM guide | done |
| Traditional Chinese, 20sp base, 64dp chapter targets | done |
| `latest.json` update check | done (silent when offline) |

## Known gaps

- **Not run on a device.** The first launch, first playback and the screen-off test are
  unverified. Everything else is verified: it compiles, it signs, it is on the Release page,
  and the audio URLs it streams from return HTTP 200 with range support.
- **`FEED_URL`, `LATEST_URL`, `RELEASES_URL`** in `app/build.gradle.kts` point at
  `wwkzorin1958.github.io/mormon-cantonese` and the GitHub Releases page. Change them only if
  the repository is ever moved.
- **No instrumented tests yet.** The manifest parser and the Chinese numerals live in the
  Python tooling, not here, so the risk is low — but the playback service deserves a smoke
  test.
- **No shuffle, no search, no playlists.** Deliberate, see the spec.

```
  ui/Theme.kt               colours + enlarged type scale

  util/Battery.kt           exemption request, per-OEM guide selection
```

## First device test

1. `adb install -r app/build/outputs/apk/debug/app-debug.apk`
2. Launch → the intro dialog appears once.
3. Tap a chapter → audio should start within a few seconds while online.
4. Lock the screen → playback continues; notification shows the title.
5. Force-stop the app → relaunch → 繼續聆聽 shows the right position.
6. 設定 → 下載全部 → wait → enable airplane mode → play a downloaded chapter.
7. Leave it playing with the screen off for two hours. If it stops, the battery guide did
   not take effect on that phone.
